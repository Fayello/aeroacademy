## fork() — How Processes Are Born

Every process (except PID 1) is created by `fork()`. The parent process splits into two — parent and child — with identical memory.

```c
pid_t pid = fork();
if (pid == 0) {
    // child process
    exec("/bin/ls");  // replace memory with new program
} else {
    // parent process
    waitpid(pid);     // wait for child to finish
}
```

**On the command line:**
```bash
# These two lines do the same thing
ls
/bin/ls

# The shell forks, then the child execs /bin/ls
```


## Process States

```bash
ps aux | awk '{print $8}' | sort | uniq -c
# 12 S    (sleeping — waiting for I/O or signal)
#  3 R    (running — actually on CPU)
#  1 Z    (zombie — exited but parent hasn't collected it)
#  2 T    (stopped — paused by signal)
#  1 D    (uninterruptible sleep — waiting for disk, can't be killed)
```

- `S` (sleeping): Normal. Waiting for input.
- `R` (running): Actually executing on CPU.
- `Z` (zombie): Dead but not cleaned up. Parent's fault.
- `D` (uninterruptible): Waiting for disk I/O. Can't be killed. If you see many, disk is slow.


## The Scheduler

The kernel decides which process runs when. It's not round-robin — it uses priorities and time slices.

```bash
# Nice value (-20 to 19, lower = higher priority)
nice -n -5 ./heavy-computation    # run with higher priority
renice -n 10 -p 1234              # change priority of running process

# Real-time priorities (0-99, higher = higher priority)
chrt -p 50 1234    # set to real-time priority50

# Check scheduling policy
chrt -p 1234
# pid 1234's current scheduling policy: SCHED_OTHER
# pid 1234's current scheduling priority: 0
```

**CFS (Completely Fair Scheduler):**
Linux uses CFS for normal processes. It gives each process a virtual runtime — processes that have run less get the CPU first. It's "fair" in that no process starves.


## Signals — How to Talk to Processes

```bash
# Send a signal
kill -SIGNAL PID
kill -9 PID          # SIGKILL — forced kill
kill -15 PID         # SIGTERM — graceful shutdown
kill -HUP PID        # SIGHUP — reload config
kill -STOP PID       # pause
kill -CONT PID       # resume

# Common signals
SIGHUP   (1)    Terminal hangup / reload config
SIGINT   (2)    Interrupt (Ctrl+C)
SIGKILL  (9)    Forced kill (can't catch)
SIGTERM  (15)   Graceful termination
SIGSTOP  (19)   Pause (can't catch)
SIGCONT  (18)   Resume
SIGSEGV  (11)   Segmentation fault
```

**Process can catch signals:**
```bash
# Trap SIGHUP in a script
#!/bin/bash
trap 'echo "Reloading config..."; reload_config' HUP
while true; do sleep 1; done
```


## /proc — The Virtual Filesystem

`/proc` isn't on disk. It's generated by the kernel. It shows you what's happening inside.

```bash
# Process info
cat /proc/1234/status
cat /proc/1234/cmdline | tr '\0' ' '
cat /proc/1234/fd/    # open file descriptors
ls -la /proc/1234/fd/ # what files are open

# System info
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/interrupts
cat /proc/loadavg
```


## Real Task: Find the Zombie

```bash
# Find zombies
ps aux | awk '$8=="Z"'

# Find parent of zombie
ps -o ppid= -p <zombie_pid>

# Check parent process
ps aux | grep <parent_pid>

# If parent is init (PID 1), zombie will be reaped automatically
# If parent is a misbehaving app, restart the parent
```
